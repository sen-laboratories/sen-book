- [[Gregor Rosenauer]]
- While there are many promising approaches and solutions to tackle notes linking and tagging, like the free [[Obsidian]] or [[Notable]], or commercial solutions like [[Notion]] and [[Roam]], these solutions neglect the fact that knowledge is not only contained in notes and _nodes_, but more in their relations (think "linked entities", see also [^png-intro]), and they force users into their ecosystem, requiring them to import any data to be linked.
- For a personal knowledge graph to be truly personal, it should not (only) live in the cloud or be controlled by an external entity, but live in user space, right at the user's finger tips. It should allow the manipulation and navigation of user data in a familiar environment, which was designed for this in a most efficent and direct way - and this is still first and foremost the desktop environment.
- Previous research following this approach tried to create a "semantic desktop" [^semdesk] fully based on semantic web technologies like [[OWL]] and [[RDF]], causing a significant overhead for desktop users in terms of performance penalties (introducing heavyweight standards and constantly scanning files for metadata) and administrative overhead (using a separate database), or tried to introduce (yet another) specialized filesystem, like [^lifs].
- As a consequence, even efforts like [^nepomuk] based on established desktops failed to generate much traction and only a minimal subset survived, like showing metadata for photos or audio files in the file browser, or providing a standard set of labels like in [[MacOS]], which are rarely used.
- SEN [^sen] (Semantic ExteNsions) avoids the aforementioned pitfalls by utilizing any existing filesystem - with the only requirement of supporting extended attributes - and stores relation references and properties in file attributes, adding a simple and thin but poweful layer to the desktop.
- By minimal extensions to the file browser (e.g. adding a menu "Open reladed..." in [[Dolphin]] for [[Linux]], or [[Tracker]] for [[Haiku]]), users can navigate to related files just like any other file operation.
- Going futher, using files to represent common desktop but also real world entities (e.g., Web URLs in [[MacOS]] and [[KDE]], but also contacts, e-mails and even books or locations - an approach used in [[BeOS]] and [[Haiku]]), you can build a personal knowledge graph directly on your desktop without the need for specialized applications, data formats, or external services.
- Files and documents stay unchanged, but get semantically enriched by extracting information for later linking and searching into attributes. This can be done automatically via separate tools for document information extraction and e.g. NER or TOC extractors (following the [[UNIX]] philosophy of loosely coupled tools), or manually added by users. 
  These attributes are then defined as part of relations, which realize the linking of information, allowing for search, referencing, and navigation.
- Relations can point outward (book "file" to author, a note referencing a section of a paper, an include relationship between source code files), or even inward, allowing to quickly navigate information inside a file, e.g., jumping into chapters of a PDF document, scenes in a video, or method declarations in source code.
- Together with file "entities", and by keeping attribute names compatible (through some standardization and normalization, e.g. by using aliases or ontologies from previous semantic desktop projects like [[NEPOMUK]] and [[OSCAF]] at freedesktop.org), users can transparently form and utilize ontologies, which provide a natural, simple and powerful way to work within the user domain, but using common desktop environments.
- For the first protoype, SEN is implemented on top of [[Haiku]] [^haiku], an open-source re-implementation of [[BeOS]], which was very innovative to provide a metadata filesystem already back in the 1990s (relations were even planned and documented at first, but later dropped because of performance and time constraints, both of which are now resolved).
- Later, the system may be realized on [[Linux]] (e.g., using [[KDE]], which provied many needed functionality out the box).
- Using SEN as a foundation, applications can integrate into the knowledge graph very simply, since they only need to work on a file level and use the thin SEN API to add linking and navigation, including querying for related entities. As a prototype showcase, a universal notebook (UNO) will be shown, which extends the standard text editor "StyledEdit" and allows referencing other files (viewed as entities), and navigating them in the file browser. The protoype will use a simple "ontology" to reference books, papers and other notes to form a digital "[[Zettelkasten]]".
